# Resident forest meshlet culling, stage 1

This branch adds an opt-in raster path at `forest-game.html?meshlets=1`. The normal URL continues to use the existing instance culler. Full geometry in the detail menu still selects level zero. Path tracing, shared BLAS/TLAS, materials, transport, forest assets and native rendering are outside this change.

The worker retains the existing four `forestDetailLevels` results. It partitions each result deterministically by triangle centroid Morton order, with at most 64 triangles and 64 referenced vertices per leaf cluster. Triangle winding, multiplicity, original vertex words, normals, baked material colors and leaf masks are retained. This small JavaScript builder follows the cluster concepts in [meshoptimizer's official documentation](https://github.com/zeux/meshoptimizer#clusterization); it does not call the meshoptimizer clusterizer or claim its partition quality. The already bundled meshoptimizer 1.3.0 simplifier continues to generate LOD geometry.

An eight-way hierarchy contains conservatively inflated float32 spheres and preorder escape links. An instance chooses one whole-model LOD, then compute traverses that level's hierarchy. A rejected parent skips its complete subtree. Visible leaves append the original instance ID to fixed-capacity draw lists. Each list can hold every instance of its model, so visibility cannot overflow under valid input. Indirect commands use `firstInstance = 0`; the existing material vertex shader reads the list offset through its batch uniform. [The WebGPU draw documentation](https://developer.mozilla.org/en-US/docs/Web/API/GPURenderPassEncoder/drawIndexedIndirect) describes that portable command layout and the optional nonzero first-instance feature. Compute and ordinary vertex/fragment pipelines are the execution path; mesh shaders are not required. [GPUWeb's explainer](https://github.com/gpuweb/gpuweb/blob/main/explainer/index.bs) describes compute-based culling and portability constraints.

LOD selection uses cumulative maximum simplifier errors, instance scale, the closest root-sphere depth and the existing 540-pixel projection. Demotion requires error below 90% of the selected pixel threshold; promotion retains the original threshold. This reduces threshold chatter while keeping the error budget. All clusters of an instance share a level, so this stage introduces no mixed-LOD boundaries. Existing simplifier error values are estimates, and visual transition acceptance remains a GPU/browser gate. The full-resolution mode preserves exact source triangles and is the comparison reference.

Clustered models are chosen deterministically using a size/work priority, within 8,192 indirect commands, 64 MiB of instance-list storage and 16 MiB of hierarchy storage. The original whole-model list allocation is the fallback floor. Models that would exceed the extra budget retain their complete original LOD draw; no geometry is truncated to fit. The GPU uses one compute dispatch per frame, six storage bindings, a workgroup size of 128, and the existing render bundle. Cached sunlight still draws complete level-zero meshes, independent of camera cluster visibility. This stage has no occlusion, cone, normal-cone or leaf-component pruning.

`forestGame.snapshot()` exposes build policy, source hashes, allocation counts and dispatch counts. `inspectDraws()` returns instance/triangle counts from a dedicated cull at current settings. `inspectMeshlets()` forces counters for its dedicated cull and returns visible root instances, tested/rejected hierarchy nodes and an overflow flag. The reader suspends new frame submission, drains old in-flight work, writes current uniforms, clears commands/counters, dispatches and reads in queue order. A requested flag can no longer label older disabled counters as enabled. Live diagnostic node counters remain optional through `meshletStats=1` or `setMeshletStats(true)`; they are off during ordinary rendering to avoid global-atomic contention. Benchmark with counters off and collect diagnostic counts separately. GPU timing remains the existing timestamp measurement when supported. CPU work counts do not establish GPU speed. This readback correction has CPU scheduling tests; its live GPU check is pending.

The CPU measurement of the unchanged 1,220,375-instance forest selects 11 clustered models and 453 complete-model fallbacks, with 8,189 indirect draws, 9,150 hierarchy nodes and one dispatch of 9,535 workgroups. Draw-list storage is 35,141,712 bytes, versus 19,526,000 bytes in the original path; hierarchy storage is 292,800 bytes. Existing resident vertex/index data remains 465,192,680 bytes. Cluster preprocessing took about 9.7 seconds on this host, beyond about 13.8 seconds for the existing LOD/instance build. Timing is informational and is not part of the deterministic buffer hash.

At 0.75 px with the same coherent LOD/hysteresis policy, submitted triangle counts drop 1.58% in Trail, 2.57% in Canopy, 10.00% under crowns, 1.05% in Clearing and 0.009% in Overview. Full-detail reductions are 0.65%, 2.09%, 8.75%, 0.36% and 0.018%, respectively. These are CPU visibility/work counts; they exclude mask-clipped triangles exactly as the original indexed draw count does and are not measured GPU performance. The limited Overview gain and extra draws/storage argue for retaining opt-in status until runtime measurements establish a benefit.

Build provenance is recorded in `MESHLET_RASTER_PROVENANCE.json`: original public commit, original and changed file SHA-256 values, and the unchanged `SOURCE_BASELINE.json` digest. The measurement script also hashes original asset payloads, implementation files and all generated buffers. Output order, packing, budget decisions and hashes do not depend on build timing.

Run CPU checks with `node --test browser/meshlet-hierarchy.test.mjs browser/forest-detail.test.mjs`. Where child-process launching is unavailable, `node -e "Promise.all(['./browser/meshlet-hierarchy.test.mjs','./browser/forest-detail.test.mjs'].map(x=>import(x)));"` runs the same Node tests in one process. The existing Naga validator checks `browser/forest-meshlet-cull.wgsl` without optional capabilities. Run `node tools/measure_forest_meshlets.mjs <original forest asset directory> <report.json>` to count the real forest's resident bytes and projected work without requesting a GPU.

Before enabling this path by default, the serialized GPU owner must compare GPU draw counts with the CPU oracle, check full-detail images at all five named views, walk through LOD boundaries and frustum edges without missing geometry, and measure median/p95 GPU times at equal settings. Reject a default switch if added compute, draw or allocation costs outweigh the triangle reduction. CPU clipping tests and coherent LOD cuts support correctness but do not certify absence of visible popping on a device.

The first safe native GPU evaluation of commit `4eb8197` used Chrome 145 on NVIDIA Lovelace. Four synthetic GPU/CPU visibility cases passed with zero overflow. At matched 0.75 px settings, mean Trail GPU time increased from 12.665 to 13.829 ms (9.2%); under crowns increased from 1.847 to 2.035 ms (10.2%). Trail mean frame interval increased from 13.077 to 14.638 ms. Startup increased from 18.725 to 25.558 seconds; worker elapsed time from 15.410 to 21.044 seconds. Queue-submission CPU p95 was about 0.1 ms for both; full frame CPU cost was not measured. The worker was not promoted, merged or deployed. All owned browser/daemon/server processes were released at 20:06:43 UTC after 82 seconds, with pre-spawn argument allowlist receipts.

These timings identify a regression, but do not isolate its complete cause. The fine path expands 1,856 whole-model commands to 8,189 commands (4.41 times as many), adds hierarchy traversal and list writes, and increases draw-list storage by 15.6 MB while retaining the same resident geometry bytes. Those are concrete overhead candidates. Separate compute/render timestamps and complete frame CPU measurements were not captured. Although cameras and the selected pixel setting match, the new LOD hysteresis differs from the baseline selector and may change submitted detail. Actual corrected diagnostic draw counts and a fine-versus-grouped comparison with unchanged LOD policy are needed to attribute the remaining cost.

Saved full-detail image pairs were inspected after release. Under-crowns pixels are identical. Trail differs at 20 of 1,008,640 pixels (0.00198%), with a maximum RGB channel difference of 6/255 and RMSE 0.00643/255. The pairs show no missing geometry. Settled 0.75 px captures after detail-control changes show coherent crowns and ground. Static captures do not certify continuous popping behavior or all named views.

Only one performance change is staged for the next measurement: `?meshlets=1&meshletGroup=8` submits up to eight adjacent existing fine meshlets as one conservative indexed draw. It uses their existing coarse hierarchical sphere, skips per-meshlet traversal/submission inside the accepted group, and retains exact vertices, indices, model set, LOD policy and shader. Fine mode (`meshletGroup=1`, the existing default experiment) remains available. Admission still uses fine budgets so spare grouping capacity does not add more models and confound the comparison. Whole-model fallback remains for every unadmitted model. No runtime auto-tuning, offline asset loader, mesh shader, streaming or occlusion mechanism is added.

CPU counts for the same 11 admitted models reduce indirect draws from 8,189 to 2,630, hierarchy nodes from 9,150 to 2,776, and draw-list bytes from 35,141,712 to 21,439,392. At 0.75 px the coarser groups retain 0.97% Trail and 8.19% under-crowns triangle savings (versus 1.58% and 10.00% in fine mode). This deliberately trades fine rejection for lower submission/traversal cost; GPU benefit is unmeasured. The next bounded GPU comparison should keep cameras/settings/counter mode equal and reject grouped mode as default if it still loses. Offline precomputation would target the measured 5.6-second extra worker cost but would not remove the draw/traversal regression; it is deferred. The existing default URL remains the cost-aware whole-model choice because measured 1–10% triangle savings did not offset GPU cost.

Streaming remains staged architecture: leaf draw ranges and model/level roots identify resident geometry, and fallback always selects a complete model level. A later residency table must make an entire selected cut available before replacing its fallback; partial page arrival must never remove fallback geometry. This branch has no fetching, eviction, compressed pages or virtual geometry. It is not full Nanite and does not address the separate Adreno path-tracing shader compilation failure.
